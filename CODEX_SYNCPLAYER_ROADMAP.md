# SyncPlayer — гибридный поиск и совместный просмотр

## Что уже работает

SyncPlayer использует Node.js 24, Express, `ws`, браузерные ES-модули, HTML5 Video и HLS.js. `RoomStore` хранит очередь, роли и состояние воспроизведения. API проверяет Origin и сессию комнаты. WebSocket передаёт состояние участникам, а `PlayerController` применяет команды и корректирует позицию. Постоянная комната переживает перезапуск.

Сохраняем загрузку файлов, прямые ссылки, диагностику, существующие адаптеры YouTube, Twitch, Vimeo, Kodik, Rutube и CVH, каталоги YummyAnime и LordFilm, поиск по названию, расписание и рулетку. Текущий процесс выкладки через `deploy/deploy.sh` и переключатель релизов LXC описан в [README](README.md) и [deploy/README.md](deploy/README.md).

## Этапы

### 1. Статический серверный поиск

- Извлечь ссылки из HTML5 `video` и `source`, Open Graph, структурированных метаданных и известных iframe.
- Начать с разрешённых HTTPS-доменов, ограниченного размера ответа и проверенного публичного DNS. Браузер получает кандидата через существующий плеер и очередь. Сервер загружает только HTML страницы и показывает ограничения по неподдерживаемым кандидатам.
- Критерий приёмки — добавить MP4, WebM или HLS из списка результатов, проверить play/pause/seek и вход в уже идущий просмотр двумя клиентами.

### Вне очереди. Владение постоянной комнатой

- При создании или закреплении постоянной комнаты привязать её к профилю создателя с ником и паролем. Роль ведущего по-прежнему может перейти к другому участнику.
- Разрешить закрыть комнату из приглашения после выхода и перезапуска. Проверить, что участник с ролью ведущего не получает право удалить чужую комнату.
- Для старых комнат без профиля предусмотреть назначение владельца администратором LXC с резервной копией.

### 2. DASH и готовность участников

- Добавить DASH/MPD через локально поставляемый MSE-плеер для открытых потоков, с проверкой CORS, форматов и ошибок.
- Показывать для выбранного источника состояние каждого участника: загрузка, готов, буферизация, недоступен. Ограничить частоту обновлений и сбрасывать состояние при смене источника или отключении клиента.
- Проверить подключение к текущему видео, коррекцию рассинхронизации и поведение группы, если один из участников буферизуется или получает ошибку.

### 3. Расширение Manifest V3 для Chromium и Firefox

- Запускать анализ только по действию пользователя в активной вкладке. Начать с DOM и HTML5 `currentSrc`, затем добавить доступные наблюдения за медиазапросами, включая динамические, с минимальными разрешениями. Показывать тип и качество, если они известны.
- Передавать только выбранный безопасный публичный URL. Привязать отправку к комнате и конкретному действию короткоживущим одноразовым кодом. Не читать и не передавать cookies, токены авторизации, сетевые заголовки или историю просмотра.
- Использовать общие модули и отдельные пакеты для Chromium и Firefox. Для событий фонового контекста использовать service worker в Chromium и event page в Firefox. Сверять разрешения на доступ к iframe и запросам отдельно в каждом браузере. [Документация WebExtensions](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background).
- Перед выпуском установить и проверить обе сборки, включая передачу в одну комнату из Chromium и Firefox. Оформить инструкции локальной установки. Публикация в Chrome Web Store и Firefox Add-ons идёт отдельным этапом.

### 4. Гибридный список источников

- Начинать с серверного поиска. При пустом результате, ошибке или динамическом плеере предлагать поиск в активной вкладке через расширение.
- Объединять кандидатов с указанием источника, типа и качества. Удалять дубликаты по каноническому URL и ID провайдера, не смешивая разные варианты качества. Воспроизводить выбранный источник в SyncPlayer.
- Истекающие адреса, требующие авторизации или привязанные к устройству, отмечать отдельно. Для разрешённых провайдеров хранить публичный исходный URL и повторно разрешать его при истечении. Не передавать подписанные приватные ссылки в комнату.

### 5. Адаптеры для динамических сайтов

- Расширять список сайтов проверяемыми адаптерами. Опциональный yt-dlp и отдельный Playwright worker допустимы только после тестирования изоляции файлов, процессов и исходящих запросов, включая DNS, редиректы, API и CDN. Настроить лимиты CPU, памяти, времени, размера вывода и параллелизма. Установку и доступность проверять в реальном окружении.
- Не скачивать ролики для обнаружения. Использовать только свойства открытых источников. Не переносить браузерные сессии в серверный worker. DRM, платный доступ, логин и ограничения встраивания не обходить. До подтверждения изоляции worker выключен.

### 6. Отдельный режим синхронизации исходной вкладки

- Для совместимых HTML5-плееров каждый зритель открывает исходную страницу у себя. Расширение применяет play/pause/seek/rate и учитывает ревизии комнаты, буферизацию, SPA, несколько видео и границы iframe.
- Тестировать двумя независимыми профилями. Этот режим передаёт команды управления оригинальной вкладке; гибридный поиск сам по себе воспроизводит выбранный источник в SyncPlayer.

### 7. Опциональная трансляция вкладки по WebRTC

- Сначала проверить согласие пользователя, tabCapture/getDisplayMedia, аудио, STUN/TURN и нагрузку.
- Первый релиз — один вещающий и один зритель с явной остановкой. Медиа идут по WebRTC, существующий WebSocket используется для сигнализации. Расширять число зрителей после измерений.

## Порядок выпуска

1. Прочитать AGENTS.md, README.md, SECURITY.md, [журнал](docs/CODEX_PROGRESS.md) и актуальные исходники. Сверить рабочее дерево, ветку, GitHub и фактический релиз LXC.
2. Выполнить один законченный этап или выделенный подэтап. Не повторять выпущенное. Для серверного поиска проверять точные хосты и DNS, закреплять соединение на проверенном IP, ограничивать время и размер ответа. Не принимать пользовательские заголовки или cookies. Все запросы после редиректов требуют отдельной проверки. Ограничения и ошибки показывать пользователю.
3. Запустить `npm run check`, релевантные браузерные тесты и при изменении зависимостей аудит. Проверить роли и сохранение текущих комнат.
4. Сделать коммит и развернуть проверенный SHA штатным способом; не перезаписывать production-настройки. Проверить health, новые функции и воспроизведение двумя участниками. При регрессии использовать штатный откат.
5. Обновить журнал с фактическим статусом, результатами, SHA, блокерами и следующим шагом. Не отмечать невыполненный деплой как успешный. После одного этапа остановиться и доложить результат.
