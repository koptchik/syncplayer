# Syncplayer

Кросплатформенный браузерный плеер для совместных вечеров: комната по ссылке, видео с устройства, YouTube, Twitch, очередь и чат. Интерфейс на русском, адаптирован для компьютеров и телефонов.

## Что работает

- Создание временных комнат и вход по приглашению; до 32 участников.
- Все участники управляют воспроизведением, паузой, перемоткой, скоростью и выбирают видео из очереди. Добавляет и удаляет видео ведущий.
- Состояние передаётся через WebSocket. Последняя принятая сервером команда действует для всех. Участник, который последним управлял плеером, обновляет позицию каждые 3 секунды; устаревшие фоновые обновления отклоняются. Остальные корректируют расхождение больше 1,2 секунды.
- Файлы загружаются на сервер и передаются участникам потоково с HTTP Range. У друзей исходный файл не требуется.
- Очередь, удаление видео, чат, реакции, список участников, восстановление сессии после обновления страницы.
- При потере соединения локальный просмотр приостанавливается. Участники могут продолжить без ведущего; комната ставится на паузу, когда отключаются все.

## Запуск

Нужен **Node.js 24 LTS**. На этой машине он уже установлен в `.tools/node/`, зависимости также установлены.

```sh
./run.sh
```

Откройте **http://127.0.0.1:3000**. Создайте комнату, добавьте видео и отправьте приглашение. Для проверки двух участников откройте ссылку в другом браузере или отдельном приватном окне.

На другой машине установите Node.js 24, затем:

```sh
npm ci
npm start
```

На Windows также можно запустить `run.cmd` после `npm ci`. На macOS/Linux — `./run.sh`. Клиент работает в современном браузере; отдельная установка на устройства зрителей не нужна.

## Доступ друзьям

`localhost` и `127.0.0.1` доступны только на самом сервере. Для локальной сети скопируйте `.env.example` в `.env` и укажите реальный адрес компьютера, например:

```dotenv
HOST=0.0.0.0
PORT=3000
ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.50
```

Перезапустите сервер, откройте `http://192.168.1.50:3000` и копируйте приглашение уже с этого адреса. Разрешите входящие подключения к порту 3000 в локальной сети.

Для интернета нужен доступный сервер, домен и HTTPS reverse proxy. Пример конфигурации — `Caddyfile.example`. Установите `PUBLIC_ORIGIN=https://watch.example.com`; оставьте Node.js на `127.0.0.1:3000`. Прокси должен сохранять `Host` и поддерживать WebSocket. При таком режиме сессионные cookies получают флаг `Secure`. Не публикуйте HTTP-сервер напрямую в интернет. TLS не настраивается автоматически самим приложением.

## Приглашения через публичный домен

Для текущего сервера в `.env` настроено:

```dotenv
PUBLIC_ORIGIN=https://stream.koptchik.duckdns.org
```

Приглашения всегда используют этот домен, даже если ведущий открыл плеер через localhost или локальный IP. Адреса из `ALLOWED_HOSTS` продолжают работать через HTTP для локальной сети; cookies на публичном HTTPS-домене получают `Secure`, а на локальных адресах — нет. Сессии браузера на разных адресах независимы: открывайте комнату ведущего по тому же адресу, по которому создали её.

В Nginx Proxy Manager: Domain Names — `stream.koptchik.duckdns.org`, Scheme — `http`, Forward Hostname/IP — `192.168.0.10`, Forward Port — `3000`, Websockets Support — включён. Выпустите сертификат для этого домена и включите Force SSL. Сервер должен быть доступен машине с NPM по локальной сети.

После изменения `.env` перезапустите `./run.sh`. Старые комнаты после перезапуска не восстанавливаются; приложение предложит создать новую вместо повторного входа по устаревшей ссылке.

## Поддержка источников

| Источник | Возможности и ограничения                                                                                                                                                                                                  |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Файлы    | MP4, WebM, M4V, MOV, MKV принимаются на загрузку. Реальное воспроизведение зависит от кодеков браузера. Рекомендуются MP4 H.264/AAC или WebM VP8/VP9/Opus. Транскодирования и выбора встроенных дорожек MKV пока нет.      |
| YouTube  | Обычные ссылки, youtu.be, Shorts, live. Используется официальный IFrame API; видео с запретом встраивания, региональными или возрастными ограничениями могут не играть. Реклама и буферизация могут нарушать синхронность. |
| Twitch   | Каналы и записи VOD; используется официальный Player API. Для опубликованного сайта нужен HTTPS-домен. У прямого эфира нет общей точной перемотки; задержка зависит от Twitch. Clips не поддерживаются.                    |

Браузер может запретить автоматический запуск со звуком. Тогда нажмите кнопку включения просмотра в плеере. Скорость Twitch всегда равна 1. Следующее видео в очереди выбирается после окончания текущего и ожидает запуска любым участником.

Документация интеграций: [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference), [Twitch Player API](https://dev.twitch.tv/docs/embed/video-and-clips/), [требования Twitch к встраиванию](https://dev.twitch.tv/docs/embed/).

## Конфигурация и хранение

Настройки перечислены в `.env.example`. По умолчанию: файл до 4 ГиБ, суммарное хранилище до 10 ГиБ, 100 комнат, 100 видео в очереди, время жизни комнаты 24 часа. Передача файла ограничена одним часом; в комнате одновременно загружается один файл, на сервере — четыре.

Комнаты, сообщения и сессии хранятся в памяти **одного процесса** и сбрасываются при перезапуске. Файлы находятся в `.data/uploads/`. Истёкшие комнаты и их файлы удаляются фоновым заданием. После перезапуска оставшиеся файлы недоступны и удаляются после истечения TTL от времени загрузки; до удаления они учитываются в квоте. Не запускайте несколько экземпляров с одним `DATA_DIR`.

## Разработка и проверка

Если Node.js установлен только локально, сначала выполните:

```sh
export PATH="$PWD/.tools/node/bin:$PATH"
```

```sh
npm run dev          # сервер с перезапуском при изменениях
npm run check        # ESLint, Prettier, серверные и security-тесты
npm run test:e2e     # Chromium: два клиента и мобильный интерфейс
npm run format      # форматирование
npm audit           # известные уязвимости зависимостей
```

Перед первым браузерным тестом на новой машине: `npx playwright install chromium`. На некоторых Linux-дистрибутивах понадобятся системные зависимости Chromium. На текущей машине тестовый Chromium установлен и запускается.

- `src/server/` — HTTP API, комнаты, проверки данных и WebSocket.
- `public/` — интерфейс, клиент комнаты и адаптеры плееров.
- `tests/server.test.mjs` — авторизация, синхронизация, загрузки и проверки безопасности.
- `tests/browser/` — реальные браузерные сценарии.
- `tests/fixtures/sample.webm` — синтетическое тестовое видео, созданное FFmpeg.

Сборка не требуется: браузер получает ES-модули напрямую. Скриншоты и трассировки тестов находятся в `test-results/`. Внешние YouTube/Twitch не являются стабильной частью автоматических тестов: проверка ссылок и обработки ошибок не доказывает доступность конкретного видео у пользователя.

## Безопасность

См. `SECURITY.md` для модели доступа, реализованных ограничений и границ проверки. Ссылка комнаты является приглашением: любой получивший её может войти. Это приложение для доверенной компании; регистрации, модерации и паролей на комнаты пока нет.


## Деплой в LXC на Proxmox

Для выкладки создай в GitHub репозитории отдельный **read-only Deploy key**. LXC должен работать под отдельным пользователем `deploy`, а приложение — под системным пользователем `syncplayer`.

1. На LXC создай SSH-ключ без парольной фразы для клонирования только этого репозитория: `/home/deploy/.ssh/github_syncplayer_deploy`. Добавь файл `.pub` как deploy key репозитория без `Allow write access`. Закреплённый SSH host key GitHub хранится в `deploy/github.com.known_hosts`.
2. Пользователем `deploy` клонируй репозиторий в `/opt/syncplayer/repo`.
3. От root в LXC запусти `bash /opt/syncplayer/repo/deploy/setup-lxc.sh`. Скрипт проверяет SHA-256 официального Node.js 24.22.1, устанавливает unit systemd и `.env`, создаёт service account и разрешает `deploy` только перезапуск `syncplayer`.
4. Пользователем `deploy` выполни `/opt/syncplayer/deploy.sh main`.

Деплой создаёт новую неизменяемую версию по commit SHA, устанавливает production зависимости, переключает `current`, перезапускает службу и проверяет health endpoint. Если проверка не проходит, он возвращает предыдущую версию. Для изменения используй `git push`; для ручного отката передай нужную ветку: `/opt/syncplayer/deploy.sh main` после возврата `main` к предыдущему commit.

Приложению нужен доступ к TCP 3000 от Nginx Proxy Manager. Разреши этот порт также в Proxmox Firewall для CT 100, если защита включена. Состояние комнат хранится в памяти: перезапуск службы сбрасывает активные комнаты. Загруженные файлы сохраняются в `/var/lib/syncplayer/uploads` и переживают выкладку.
